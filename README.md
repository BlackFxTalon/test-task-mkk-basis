# Заметки

Клиентское SPA для заметок со списками задач: создание, редактирование, undo/redo, черновики сессий и безопасная работа из нескольких вкладок. Данные хранятся только локально в браузере, серверная часть отсутствует. Приложение собрано на Nuxt 4 со строгим TypeScript, без UI- и служебных библиотек: собственная SCSS-вёрстка, собственный диалог на `native <dialog>`, собственный журнал истории и ручная работа с browser storage.

## Требования

- Node.js 24+ и npm 11+ — для локальной разработки и сборки.
- Docker Engine и Docker Compose — для production-like запуска одной командой.

## Запуск в Docker

```bash
docker compose up -d --build
```

Приложение будет доступно на `http://localhost:3000`.

- Multi-stage сборка: на первом этапе `npm ci` (детерминированная установка по lockfile) и статическая генерация SPA; на втором nginx раздаёт готовые файлы.
- Контейнер содержит healthcheck — состояние можно проверить через `docker ps` (статус `healthy`) или `docker compose ps`.
- Настроен history fallback: прямые URL редактора (`/notes/new`, `/notes/<id>`) и hard reload по ним открываются корректно, без серверной 404.

Остановить:

```bash
docker compose down
```

## Локальная разработка и npm-команды

```bash
npm ci        # детерминированная установка зависимостей по lockfile
npm run dev   # сервер разработки
```

Команды проверки качества:

```bash
npm run lint        # ESLint
npm run typecheck   # строгая проверка типов (vue-tsc)
npm test            # все Vitest-наборы (история, сторы)
npm run build       # production-сборка
npm run generate    # статическая генерация SPA в .output/public
npm run preview     # локальный просмотр production-сборки
```

Сборка, которую обслуживает Docker, эквивалентна `npm run generate`: это статические SPA-файлы без серверного рантайма.

## PWA и оффлайн-проверка

Приложение устанавливается как PWA и открывается в отдельном окне. `manifest.webmanifest` задаёт имя, режим `standalone`, фирменный цвет и обязательные иконки, по которым браузер определяет устанавливаемость. Service worker создаётся `@vite-pwa/nuxt` в режиме `injectManifest` только для production-сборки:

- оболочка, манифест и иконки входят в precache;
- переходы по страницам используют network-first: при доступной сети приходит свежая оболочка, без сети — precache;
- хешированные файлы `/_nuxt/` используют cache-first;
- `registerType: 'autoUpdate'` вместе с `self.skipWaiting()` активирует новую версию без запроса пользователю; она появляется при следующем открытии приложения;
- заметки, черновики и тема хранятся в `localStorage`, поэтому чтение и редактирование продолжают работать без сети.

Для локальной проверки нужна статическая production-сборка. Dev-сервер не регистрирует service worker, а `npm run build` для этого SPA не добавляет статический `index.html` в precache, поэтому используйте `generate`:

```bash
npm run generate
npm run preview
```

Затем в текущем стабильном Chrome:

1. Откройте `http://localhost:3000`, дождитесь первой полной загрузки и перезагрузите страницу один раз, чтобы SW управлял вкладкой и runtime-кэш получил ассеты.
2. Установите приложение через значок установки в адресной строке или пункт меню браузера. Оно должно открыться без браузерных панелей в режиме `standalone`.
3. В DevTools → Network выберите `Offline` и полностью перезагрузите главную, `/notes/new` и страницу существующей заметки. Проверьте создание, сохранение, undo/redo и переключение темы.
4. Верните сеть, измените приложение, повторите `npm run generate`, перезапустите preview и снова откройте PWA. Следующее открытие должно показать новую сборку без ручного подтверждения обновления.

Иконки 192×192 и 512×512 для назначений `any` и `maskable` генерируются из `public/logo.png`:

```bash
npm run icons
```

Перезапускайте генератор после каждой замены `public/logo.png`, затем пересобирайте приложение, чтобы новые файлы попали в precache service worker.

Firefox 155 выборочно проверен при полностью остановленном preview: главная и прямой URL `/notes/new` смонтировались из кэша, данные `localStorage` сохранились. Lighthouse 13.4.1 больше не предоставляет категорию PWA (`pwa` удалена из `only-categories`); полный ориентировочный аудит прошёл со значениями Performance 95, Accessibility 100, Best Practices 96, SEO 100. Устанавливаемость вместо удалённой Lighthouse-категории проверена актуальным Chrome Installability API.

## Архитектура

Приложение разделено на слои с явными интерфейсами:

- **Домен** — типы заметки и черновика, правила нормализации и валидации, обратимый журнал истории. Не знает ни про DOM, ни про хранилище.
- **Адаптеры browser storage** — инкапсулируют чтение/запись, версионирование и миграции за портом-интерфейсом; компоненты и сторы обращаются только к публичным действиям сторов.
- **Pinia-сторы** — публичное состояние и действия для списка заметок и редактора: сортировка, валидация, черновики, конфликты ревизий, реакции на внешние изменения.
- **Компоненты** — презентация и пользовательские сценарии; работают только с публичным API сторов.
- **Тема** — самостоятельный механизм со своим ключом хранилища, не зависящий от данных заметок.

История редактирования — это журнал обратимых атомарных операций (текст заголовка, текст пункта, отметка выполнения, вставка и удаление пункта), а не копии всей заметки на каждый шаг. Непрерывный ввод в одно поле группируется в одну операцию до потери фокуса или паузы 700 мс. История ограничена 50 последними операциями, новая правка после отмены отбрасывает ветку redo, а после сохранения или подтверждённой отмены история очищается. История не сохраняется между сеансами.

## Хранение данных и версионирование

Три независимых ключа в `localStorage`:

| Ключ | Что хранит |
| --- | --- |
| `basis-notes:notes` | сохранённые заметки в версионированном конверте |
| `basis-notes:drafts` | черновики сессий редактирования |
| `notes-theme` | выбранный режим оформления |

Конверт заметок несёт `schemaVersion`. Известные старые версии поднимаются последовательными миграциями, неизвестная будущая версия и повреждённые данные считаются блокирующей ошибкой: приложение показывает явное сообщение и требует подтверждённого сброса данных, вместо того чтобы молча подменить список пустым. Сброс данных заметок не затрагивает тему. Если само хранилище недоступно (приватный режим, запрет cookies), приложение продолжает работать в памяти и не сообщает об успехе несостоявшегося сохранения.

## Черновики и сессии редактирования

Каждое открытие редактора получает собственную идентичность сессии, сохраняемую в параметре `?session=` URL, поэтому после случайной перезагрузки вкладка восстанавливает ровно свой черновик. Черновик записывается через 700 мс после изменений и дополнительно при скрытии страницы; черновики старше 30 дней удаляются при безопасной инициализации. Восстановление предлагается диалогом: можно вернуть черновик или явно отказаться (в том числе клавишей Escape). Параллельная правка одной сессии из двух вкладок блокируется: сессию занимает первая вкладка.

## Согласованность между вкладками

Каждая заметка имеет монотонно растущую ревизию. Чистый редактор автоматически принимает внешне сохранённую версию; грязный сохраняет локальную работу и сообщает о внешнем изменении. Конфликт сохранения разрешается явно: загрузить последнюю версию, сохранить свою как новую заметку или осознанно перезаписать — перезапись никогда не является действием по умолчанию. Внешне удалённая чистая заметка переводит редактор в состояние «удалена»; грязная предлагает сохранить работу как новую заметку или выйти без сохранения. Главная страница обновляется при изменениях хранилища из других вкладок.

## Тема оформления

Доступны режимы «системная», «светлая» и «тёмная»; по умолчанию используется системная. Выбранный режим применяется до гидратации (без вспышки неправильной темы) и восстанавливается при следующем визите. Палитра построена на CSS-функции `light-dark()` с управлением через `color-scheme`; в системном режиме приложение реагирует на смену темы операционной системы на лету.

## Горячие клавиши

| Действие | Клавиши | Где работает |
| --- | --- | --- |
| Отменить (undo) | `Ctrl+Z` / `Cmd+Z` | вне текстовых полей |
| Повторить (redo) | `Ctrl+Shift+Z`, `Ctrl+Y` / `Cmd+Shift+Z`, `Cmd+Y` | вне текстовых полей |
| Нативная отмена ввода | `Ctrl+Z` / `Cmd+Z` | внутри текстовых полей |
| Закрыть диалог | `Escape` | в открытых диалогах |

Диалоги удерживают фокус, закрываются по Escape и возвращают фокус на вызвавший элемент; в разрушающих подтверждениях изначально сфокусировано безопасное действие.

## Поддерживаемые браузеры

Текущие стабильные версии Chrome, Firefox, Edge и Safari. Internet Explorer и устаревшие версии браузеров не поддерживаются.

## Ограничения и сознательно исключённые возможности

- Нет серверной части, SSR, учётных записей, авторизации и облачной синхронизации — данные живут только в этом браузере.
- Нет поиска, фильтрации, меток, архивации, корзины, массовых операций, импорта/экспорта и печати.
- Нет перетаскивания, ручной сортировки, подзадач, сроков, напоминаний, приоритетов, вложений, богатого текста и многострочных полей.
- Не используются UI-, иконочные, модальные и библиотечные решения для истории: всё реализовано вручную.
- История undo/redo не переживает перезагрузку страницы.
- Дубликаты заголовков и текстов пунктов разрешены — приложение не придумывает правила уникальности.

## Чек-лист ручной приёмки

Выполнять в текущем стабильном браузере на `http://localhost:3000`.

**CRUD и список**
1. Открыть главную: пустое состояние с действием создания.
2. Создать заметку с заголовком и тремя пунктами → после сохранения вернуться на главную → карточка появилась первой, показываются заголовок, пункты и счётчик прогресса.
3. Добавить больше трёх пунктов → в превью видны первые три и «Ещё N».
4. Открыть заметку, изменить заголовок и пункты, сохранить → на главной порядок обновился, изменения видны.
5. Удалить заметку с подтверждением → карточка исчезла, операция озвучена статусом.
6. Перезагрузить страницу → все изменения сохранились.

**Валидация**
7. Попытаться сохранить заметку с пустым заголовком → инлайн-ошибка, фокус в поле заголовка.
8. Ввести заголовок длиннее 120 символов и текст пункта длиннее 300 → видимый индикатор лимита.
9. Оставить пустые строки в списке задач и сохранить → пустые пункты не сохранились; пробелы по краям обрезаны.

**Undo/redo**
10. Поставить/снять отметку, добавить и удалить пункт → каждое действие отменяется и повторяется кнопками и `Ctrl+Z` / `Ctrl+Shift+Z`.
11. Ввести текст в поле, нажать `Ctrl+Z` внутри поля → работает нативная отмена ввода; вне поля — отмена операций приложения.
12. Отменить действие, сделать новую правку → redo-ветка сброшена.
13. Сохранить заметку → история очистилась, кнопки undo/redo неактивны.

**Черновик и перезагрузка**
14. Изменить заметку, не сохранять, подождать секунду и перезагрузить вкладку → предложено восстановление черновика; восстановить → данные на месте, история пуста.
15. Повторить и отказаться от восстановления → черновик удалён, редактор на базовом состоянии.
16. Открыть `/notes/new` в двух вкладках, начать разные черновики → вкладки не подменяют черновики друг друга.

**Две вкладки и внешние изменения**
17. Открыть одну заметку в двух вкладках. В вкладке А сохранить правку → чистая вкладка Б обновилась автоматически.
18. Сделать грязную правку в Б, затем сохранить в А → Б сохранила локальную работу и показала конфликт; выбрать «загрузить последнюю версию» / «сохранить как новую» / осознанную перезапись — перезапись не была вариантом по умолчанию.
19. Удалить заметку в А при открытой чистой Б → Б показала состояние «заметка удалена».
20. Удалить в А при грязной Б → Б предложила сохранить работу как новую или выйти без сохранения.
21. Открыть несуществующий URL `/notes/неизвестный-id` → страница «не найдено» с действиями «на главную» и «создать».

**Повреждённое хранилище**
22. В DevTools записать в `basis-notes:notes` некорректный JSON и перезагрузить → явное сообщение об ошибке вместо пустого списка; подтверждённый сброс очищает заметки, но тема сохраняется.
23. Записать `schemaVersion` больше известной → то же защищённое поведение.

**Тема**
24. Сменить системную тему ОС в режиме «системная» → приложение реагирует без перезагрузки.
25. Выбрать светлую и тёмную темы, перезагрузить → выбор восстановлен без вспышки неправильной темы.

**Клавиатура и фокус**
26. Пройти создание заметки только с клавиатуры: все действия доступны, фокусные кольца видимы.
27. В диалоге удаления безопасное действие в фокусе изначально; Escape закрывает диалог, фокус возвращается на кнопку вызова.

**Мобильный viewport**
28. При ширине ~375 px нет горизонтальной прокрутки, элементы управления не меньше 44 px, навигация и редактор работают.
